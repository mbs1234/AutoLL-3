# AutoLL-3 v1.8.5

Codex reviewed 1.8.4 and agreed with its fixes, with five requests. This makes
four of them and the cancellation half of the fifth. Each change below has a
test that fails without it.

- **Autopilot moves only the party.** Disney's offer for a move or a swap names
  everyone on the reservation, and Autopilot sent it as it came, so a pass shared
  with someone outside the saved party moved them too. Now only the party's
  guests are sent: Disney splits the reservation and the others keep theirs.
  Without a saved party, everyone the offer names is moved, as before.
- **The booking reader does not guess.** An answer whose only entry names
  another attraction, or that lists a booked guest without an entitlement, is
  now an unknown outcome, protected until Plans show what happened. It was read
  as a success for the attraction asked for. An entry that names no attraction
  at all is still read, and logged.
- **A cancellation clears only on proof.** 1.8.4 cleared one 30 seconds on even
  if Plans still showed its passes. A cancellation that lands late, though, can
  remove a pass changed in the meantime, so it now clears only when Plans no
  longer show the passes, or when you clear it after checking Disney. A booking
  still clears either way: Disney refuses a second booking of an attraction for
  the same guests, so whichever lands second is refused.
- **DAS has its own protection.** A DAS cancellation in doubt shared the ride's
  key with its Lightning Lanes, which paused them, and it was read against
  Lightning Lanes only, so it looked done on the next read whether or not it
  was. It now has its own key, is read against DAS selections, and the panel
  names it as a DAS selection.
- **Sign-in can be reloaded when it is stuck.** Retry joins Disney's setup
  rather than start a second one beside it, so a setup that never finishes kept
  every Retry waiting. After two timeouts in a row the card says so and offers
  **Reload the page**. The retry button is now drawn as a button; the class it
  used no longer existed, so it showed as plain text.
- **Change and Modify after removing guests** act for the guests still on the
  pass. They used to ask Disney to move the removed guests as well.

Not in this release: putting Autopilot's own lost bookings into the shared
protection, which Codex also asked for. It touches Autopilot's main loop and
is planned for after the rehearsal (`docs/FUTURE.md` §1). Disney's refusal of
a second booking covers the gap meanwhile.

Verified locally: 133 suites and 2,126 tests passed in five full runs; no
test ends with a load still showing; lint, TypeScript checking, Prettier and
the production build passed; the dependency audit reported zero
vulnerabilities. In the harness, against fake clients: after Cancel removed
one guest from a booking, Change offered the move for the two still on it,
and the move went through. No real Disney reservation was created or modified for
these checks, and the booking reader has still not seen a real Disney answer.
